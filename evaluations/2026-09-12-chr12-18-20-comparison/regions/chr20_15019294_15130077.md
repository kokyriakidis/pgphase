# chr20:15,019,294-15,130,077 competitor bridge

## Selection

This 110,783 bp graph-phase gap is crossed by HiPhase, WhatsHap, and optimized
WhatsHap with >=99% assembly-read accuracy and no GIAB switch interval. Graph
pgphase ends one shared-VCF block at 15,019,294 and starts the next at
15,130,077. The 300 kb graph-locked private-SNP bridge does not merge them.

HiPhase and WhatsHap received the same normalized linear BAM and DeepVariant

## What pgphase had

The BAM caller already reports the four private SNPs at 15,039,543,
15,039,634, 15,048,452, and 15,055,707 as `CLEAN_HET_SNP`; all have GQ 60,
58-75 reads, and VAF 0.45-0.60. It also reports the required indel anchors as
balanced `NOISY_CAND_HET` records. The graph catalog has no records in the
15,039-15,056 kb private-SNP segment or around 15,109 kb.

The clean-private selector nevertheless emits no site in this gap. It anchors
the native graph gap at 15,013,793, 25.8 kb before the first private SNP, and
requires a complete read-overlap path. Because it excludes the repeat deletion
near 15,019,294, the clean SNP chain is unreachable and is discarded.

Allowing GQ10, VAF 0.30-0.70 noisy indels only when they lie on a complete
two-sided path selects the needed boundary indels and clean SNPs. The current
hybrid still does not close the gap because its clean-core k-means excludes
those selected noisy indels. Enabling all repeat indels chromosome-wide is not
acceptable: the earlier ablation raised read Hamming to 3.78%.

Using completed BAM phase sets as graph-lock bridge evidence also fails here.
The BAM pipeline splits the chain into phase sets at 15,039,543, 15,071,132,
and 15,101,262, so no single BAM block links both graph endpoints.

## Required fix

Add a bridge-only allele graph after graph phasing:

1. Seed it with immutable left/right graph phase blocks.
2. Add BAM-clean SNPs inside the gap.
3. Add a noisy/repeat indel only when it is necessary for a complete path,
   has GQ >=10, VAF 0.30-0.70, MAPQ20 support, and a winning allele-link
   orientation of at least 2 reads and a configurable margin.
4. Resolve orientation transitively from allele-link edges instead of requiring
   one pre-existing BAM or hybrid phase set to touch both graph blocks.
5. Merge only when both graph endpoints agree with the inferred parity; retain
   all original graph read assignments.

This uses information already available to pgphase. The missing capability is
the transitive bridge graph and targeted admission policy, not another caller
or additional sequencing data.

## Private-site MSA experiment (2026-09-13)

Code inspection corrected an important assumption about the BAM pipeline.
First-pass repeat indels create noisy intervals, but successful MSA calls are
labelled `NOISY_CAND_HET/HOM`; they are not promoted to `CLEAN_HET_INDEL`.
The BAM pipeline phases them only because its second k-means uses the broader
`kCandGermlineVarCate` mask. Hybrid normally skips that second k-means because
the chromosome-wide noisy pass previously increased error. Graph+private mode
also disabled MSA completely with `max_noisy_reg_len=0`.

An experimental `--private-msa` mode now runs MSA only for noisy intervals
containing a whitelisted private key, admits only exact-key MSA calls, and
re-phases those calls with the clean graph core. Exact collisions with retained
`REP_HET_INDEL` rows use the MSA call and MSA-derived read profile. Unlisted MSA
calls remain excluded.

On `CHM13#0#chr20:14,950,000-15,180,000`, the seven-site sparse whitelist
admitted four MSA het indels and expanded the central block through 15,095,642.
A complete 26-record path phased 554/1,034 reads with zero truth-discordant
reads, versus 483/1,034 for the sparse path, but still produced three blocks.
The unified matrix explains the residual breaks: pgphase's MSA calls at
15,019,256 and 15,095,642 have no shared profile observations to the next
distant anchor. WhatsHap's shared-VCF path instead uses shifted repeat
representations at 15,019,294 and 15,095,666 and finds 4 and 16 bridge reads.
This is not an input-alignment difference: after removing the contig-name field,
the qname/flag/position/MAPQ/CIGAR records in the annotated hybrid BAM and frozen
normalized competitor BAM are byte-identical across 15.018-15.112 Mb. The loss
is in variant representation and allele-profile extraction.

The whole-chromosome safety check used the frozen 958-site GQ10 private set and
the existing `joint_gq10_ps50` command plus `--private-msa`. It did not improve
contiguity: read N50 remained 991,274 bp and switchflips remained 139. Phased
reads changed 179,494 to 179,452 and discordant reads worsened 269 to 285.
Therefore `--private-msa` remains opt-in. The next fix must reconcile equivalent
repeat alleles and score transitive bridge edges; exact-key MSA admission alone
is insufficient.

## Bridge-admission margin (2026-09-13, follow-up)

The consensus-rescoring bridge admission in `align.cpp` originally accepted a
read whenever one consensus scored *strictly* better — `if (scores[0] ==
scores[1]) continue;`. A one-point WFA gap is noise, and these reads are being
admitted into a trusted graph-phased block, so this is the same failure mode
`--min-read-margin` exists to fix in the k-means path.

Chromosome-wide gate re-run on the current tree (chr20, `joint_gq10_ps50`,
frozen 958-site GQ10 private set, truth = `diplinator_merged.bam`). Note the
frozen `commands_chr20.sh` passes `-r chr20`, but the BAM and reference both use
`CHM13#0#chr20`; the prefixed name is required.

| arm | reads | discordant | hamming | phase sets | vs baseline |
|---|---|---|---|---|---|
| baseline (flag off) | 179,494 | 269 | 0.001499 | 220 | — |
| margin 1 (original) | 179,471 | 408 | 0.002273 | 199 | +139 disc, −21 PS |
| margin 6 | 179,471 | 534 | 0.002975 | 199 | +265 disc, −21 PS |
| margin 12 | 179,455 | 285 | 0.001588 | 209 | +16 disc, −11 PS |
| margin 18 | 179,455 | 285 | 0.001588 | 214 | +16 disc, −6 PS |
| **margin 24** | 179,455 | **268** | 0.001493 | **216** | **−1 disc, −4 PS** |
| margin 36 | 179,455 | 268 | 0.001493 | 219 | −1 disc, −1 PS |
| margin 60 | 179,452 | 285 | 0.001588 | 220 | +16 disc, ±0 PS |

`--private-msa-margin` now exists, default 24 (4x the mismatch cost of 6).

Three conclusions:

1. **The committed behaviour was net-negative.** The consensus rescoring does
   merge blocks — 21 fewer phase sets, which the earlier recorded run did not
   achieve (N50 was flat there) — but at +139 discordant reads, a 52% accuracy
   regression. It is a contiguity gain bought with accuracy, not a free win.
2. **A margin makes it accuracy-neutral, and the contiguity gain mostly
   disappears with it.** At margin 24 the result is −1 discordant and −4 phase
   sets. One read out of 269 is within noise on a single chromosome, so this is
   best described as accuracy-neutral with a small contiguity gain (4 of 220
   phase sets), not as an improvement in accuracy.
3. **The response is non-monotonic and therefore not trustworthy under scalar
   tuning.** Margin 6 is worse than margin 1 (534 vs 408 discordant) despite
   admitting strictly fewer reads, and margin 60 is worse than margin 36. Admitted
   reads feed the MSA profile, which feeds k-means, which changes phase sets
   elsewhere; a single score threshold cannot control that chain. This supports
   the conclusion already recorded here: the next fix is the transitive
   bridge-edge gate and equivalent-allele reconciliation, not a better threshold.

`--private-msa` also flips `skip_noisy_kmeans = false`, so it changes two things
at once — the bridge admission and enabling the second `kCandGermlineVarCate`
k-means that `collect_pipeline.cpp` notes previously increased error. Those
should be separable before either is judged.

## Why the MSA candidates do not bridge (2026-09-13, chromosome-wide)

The premise was that MSA-confirmed noisy candidates would supply the extra sites
competitors use. Measured chromosome-wide on chr20 (hybrid, no private
whitelist, so MSA runs everywhere):

| arm | reads phased | discordant | hamming | phase sets |
|---|---|---|---|---|
| MSA candidates generated, not in k-means | 184,202 | 313 | 0.001699 | 218 |
| `--keep-noisy-kmeans` (candidates used) | 183,954 | 1,931 | 0.010497 | **218** |

**27,781 MSA candidates (22,262 het) buy zero contiguity and 6.2x the errors.**

### It is not a generation problem

MSA produces plenty, and they are heterozygous:

| | chromosome-wide | inside phase-block gaps |
|---|---|---|
| `NOISY_CAND_HET` | 22,262 (80.1%) | 1,911 (60.0%) |
| `NOISY_CAND_HOM` | 5,519 (19.9%) | 1,276 (40.0%) |

Nor are they misplaced in aggregate: 11.5% fall inside phase-block gaps, and
gaps are 11.6% of the spanned region — exactly the background rate.

### It is a *distribution* problem

Spacing between consecutive het candidates inside the gaps is what decides
whether a read can chain across them:

| source | median spacing in gaps | p90 spacing | n |
|---|---|---|---|
| **MSA het candidates** | **33 bp** | **6,935 bp** | 1,846 |
| DeepVariant het calls | 227 bp | 1,692 bp | 4,631 |

MSA fires only inside *noisy intervals*, so its output arrives as tight clusters
(33 bp apart) separated by multi-kb voids. DeepVariant calls genome-wide, so 90%
of its consecutive sites are within 1.7 kb — always read-spannable. A cluster of
21 candidates packed into one 700 bp pocket does nothing for a 26 kb gap.

Per-gap, the narrow gaps are the emptiest, which is the worst possible split
because those are the ones reads could actually bridge:

| gap width | n | median MSA het | median DV het | gaps with 0 MSA | gaps with 0 DV |
|---|---|---|---|---|---|
| 0–5 kb | 9 | 0 | 0 | 7 | 8 |
| 5–25 kb | 35 | 1 | 0 | 15 | 18 |
| 25–100 kb | 30 | 4 | 3 | 2 | 0 |
| >100 kb | 15 | 12 | 11 | 0 | 0 |

### But candidate spacing is NOT the binding constraint for most gaps

Chaining each gap as [left block end] -> het candidates inside -> [right block
start] and taking the largest consecutive step:

| gap width | n | median max-step | chain fully < 20 kb |
|---|---|---|---|
| 0–5 kb | 9 | 1,993 | 9/9 |
| 5–25 kb | 35 | 10,877 | 34/35 |
| 25–100 kb | 30 | 19,945 | 15/30 |
| >100 kb | 15 | 26,207 | 1/15 |

**59 of 89 gaps (66%) have a complete candidate chain with every step under
20 kb** — reads can cross every link. Only 30 are unbridgeable on spacing
grounds. So the spacing argument above explains the minority, not the majority.

Checking read support at every link of those chains:

| | |
|---|---|
| gaps with a chain where some link has <2 spanning reads | 3/43 |
| **gaps where EVERY link has >=2 spanning reads** | **40/43** |

Median reads at the weakest link: 21–62 depending on gap size. The candidates
exist, the reads exist, and the blocks still do not merge.

### The actual cause: the linking reads are untagged

At the weakest link of those bridgeable gaps:

| | |
|---|---|
| median spanning reads | 17 |
| median of those carrying an HP tag | **2** |
| median HP-tagged fraction | **8.9%** (chromosome-wide it is ~95%) |
| links where **zero** spanning reads carry HP | **17/42** |
| links where fewer than 2 carry HP | 21/42 |

`iter_update_var_hap_cons_phase_set` counts a linking read only through
`check_agree_haps`, which returns -1 unless `chunk.haps[read_i] != 0`. An
untagged read is invisible as linking evidence even when it spans both variants
cleanly and carries an unambiguous allele at each. With fewer than
`min_block_link_reads` (2) countable reads, the phase set breaks — and the reads
stay untagged *because* the phase set broke. Same circular failure as the graph
pipeline's junction analysis.

This also explains why the noisy candidates changed 106 of 218 phase-set ids
while leaving the count at 218: blocks *extend* into the gaps (e.g. a block start
moving 890,260 -> 882,277) but the junction itself still cannot be crossed.

### Implication (revised)

The targeted fix is **not** more candidates and **not** boundary-driven MSA for
these 40 gaps — both the sites and the reads are already present. It is to let
an untagged read contribute linking evidence: for the phase-set break decision,
what matters is whether a read's alleles at two variants co-occur consistently,
which is well defined without knowing the read's haplotype. Adding an
allele-co-occurrence linker alongside `check_agree_haps`, used only for the
break/merge decision, addresses 40 of the 89 gaps directly.

Boundary-driven MSA remains the right answer for the 30 spacing-limited gaps,
and 24 of 89 gaps have no het MSA candidate at all.

### The correction to the working assumption

**Competitors do not have more sites than us inside our gaps** — the medians are
comparable and DeepVariant is *emptier* in the narrow gaps. They have them
**evenly spaced**, because they come from a genome-wide caller rather than from a
noise-triggered trigger. Contiguity depends on consecutive-site spacing, not on
site count, so a noise-gated candidate source cannot close this gap no matter how
many candidates it emits.

### Implication for the method

MSA is being pointed at the wrong places. It examines regions selected for being
noisy; blocks break in the stretches *between* anchors, which MSA never inspects
because they look clean. The targeted fix is to drive MSA from **phase-set
boundaries** rather than from noisy intervals: run it in a window spanning each
junction between consecutive blocks, where evidence is actually needed. On chr20
that is 89 windows, against 27,781 scattered candidates today — far cheaper and
aimed at the actual deficit.

This also explains the earlier local success: the 15.02/15.10 Mb window happened
to be a junction that *was* noisy, so MSA fired exactly where it was needed.
That is the exception, not the rule — 27% of gaps contain no het MSA candidate
at all.

## Three-tier evidence escalation (2026-09-13)

Refined design per discussion: for each still-broken junction between
consecutive phase blocks, escalate through three evidence tiers in order of
trust, stopping as soon as one closes the junction:

1. **Private clean sites** (BAM-called, already depth/AF/strand-bias filtered).
2. **MSA-verified noisy SNPs** — unambiguous: a SNP call has one position.
3. **MSA-verified noisy indels** — only if SNPs alone did not bridge; an indel
   inside a repeat run can be placed at several equivalent positions, so it is
   the least trustworthy source and should be a last resort, not a default.

### Tier 1 needed no new code

Checking the retention filter in `process_chunk_hybrid`
(`src/collect_pipeline.cpp:788`) shows every private BAM candidate is dropped
outright before k-means unless it matches `--private-sites` or is inside a
BAM-authoritative region. **Without `--private-sites`, `private_keys` is null
and every clean BAM candidate already flows through unrestricted** -- which is
exactly the `noisy_skip` baseline used throughout this investigation. The 75
candidate-complete, read-covered gaps found earlier already include every
private clean site; they still do not close, because the linking reads at the
junction are untagged (established previously), not because clean candidates
are missing. Tier 1 is structural, already satisfied by the baseline
configuration, and needs no new mechanism.

### Tiers 2/3: implemented as per-junction escalation

`collect_noisy_vars_step4` (`src/collect_phase_noisy.cpp`) now runs two passes
when `--private-msa-snp-first` is set alongside
`--private-msa-admit-all-in-region`:

- **Pass 1**: every whitelist-triggered noisy region runs MSA and admits only
  SNP calls (`merge_var_profile`'s three admission checkpoints all gate on a
  new `admissible_type` predicate). K-means reruns as usual.
- **Escalation check**: for each whitelist-triggered region, walk
  `chunk.candidates` to find the nearest phased het variant before and after
  the region (`noisy_region_still_broken`) and compare their `phase_set`. If
  they still differ, the junction is still open.
- **Pass 2**: only for regions still open, retry with indels admitted too
  (SNPs already merged in pass 1 are no-ops on retry -- `merge_var_profile`'s
  exact-key merge walk leaves them untouched).

New flags: `--private-msa-snp-first` (Options.private_msa_snp_first, default
off). All 6 unit-test binaries pass; existing 4-arg `merge_var_profile` /
3-arg `collect_noisy_vars1` call sites are source-compatible via new trailing
defaulted parameters.

### Measured on the gap-window whitelist (chr20)

| arm | reads | discordant | hamming | phase sets | blocks | covered Mb |
|---|---|---|---|---|---|---|
| baseline | 184,202 | 313 | 0.001699 | 218 | 114 | 55.0 |
| gap-scoped, admit-all (no tiers) | 175,888 | 255 | 0.001450 | 223 | 130 | 52.8 |
| **gap-scoped, SNP-first then indel** | 175,888 | 255 | 0.001450 | 223 | **130** | 52.8 |

Phasing outcome (reads, discordant, blocks) is **byte-for-byte identical**
between the tiered and untiered runs -- but the admitted candidate sets are
not:

| category | admit-all | SNP-first tiered | delta |
|---|---|---|---|
| NOISY_CAND SNP | 2,232 | 2,349 | +117 |
| NOISY_CAND DEL | 400 | 233 | -167 |
| NOISY_CAND INS | 375 | 231 | -144 |

**775 fewer indel calls were admitted for the identical phasing result.** Every
indel excluded by the tier was one the untiered run had also admitted without
it changing a single downstream read assignment -- pure noise the escalation
correctly screened out. This is the outcome the design predicted: indels are
the least trustworthy source and should be used only when SNPs are not enough,
and here SNPs (plus the 117 recovered by trying harder within the SNP-only
pass) were already sufficient everywhere an indel had been admitted.

### What remains open

Both the tiered and untiered scoped runs still land on **130 blocks against
baseline's 114** -- gap-scoping plus tiering fixes the accuracy regression from
unrestricted admission (§ above, 313->1,868 discordant) but does not yet
improve contiguity over doing nothing. The blocker identified two experiments
ago stands: the reads that would link across these junctions are untagged
(median HP-tagged fraction 8.9% at the weakest link vs ~95% chromosome-wide),
and admitting more candidate *positions* does not by itself get those reads an
HP tag. The tiering makes candidate admission safer; it does not yet address
why the linking reads go untagged in the first place.
